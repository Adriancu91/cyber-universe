# P6-233 — PREDARE Cyber-GPU P2zq (`4293b5c`): `attn_back_tile_tc16_v4` și `_v4pf` lângă tc16

**Scop:** os-457 a arătat că tc16 (dQ, dK, dV pe circuitele f16) e corect, dar lent (0,87 ms la `atentie-513-b4`, > 90 % așteptare
de citiri). Cyber-GPU a scris două variante cu citiri de 128 de biți (aceeași aritmetică): trebuie să dea aceleași cuvinte ca tc16
și să fie mai rapide (prezis 0,35–0,55 ms).

**Pași:**
1. Dependența cyber-gpu `250c9b8` → `f6ce737` (strămoș verificat; doar adăugări + variante noi în `MixedLaunch` / `TcPick`,
   pe care OS-ul nu le potrivește exhaustiv — build-ul trece).
2. Opțiune nouă, oprită implicit: `test-placa … --atentie-tc --atentie-tc16-v4` (doar imediat după `--atentie-tc`).
3. `gpu_i14.rs`: `AttnTcProg::{V4, V4pf}` (SHA-256 verificat, încărcate după tc / tc16); pe fiecare set mic și pe `atentie-513-b4`,
   după tc16, pe aceleași P / dS, doar unde `fits(&args)`; altfel „nealiniat (sarit)” (nelansat — o citire nealiniată ar fi o eroare).
   dqkv umplut cu NaN înainte; cuvintele comparate cu ale lui tc16; garda verificată; timpii (mediana a 5 la set mare).
4. Rânduri noi: `kt atentie-tc16-v4 set N`, `atentie-tc16-v4 (vechi langa nou, …): TRECE / NU TRECE: …`; valorile de jurnal
   `kt atentie-tc16-v4 seturi v4 = tc16`, `… v4pf = tc16`, `kt atentie-tc16-v4 mare timp v4 / v4pf (ns)`.
   Verdictul lui `atentie-tc` (tc / tc16) nu se schimbă.
5. Build-ul de test: `gpu atentie-tc-sim on v4`, înlocuitorii `gpu-sim` înregistrați; scenariul `kronos-gpu-atentie-tc-v4`.

**Fișiere:** `kernel/Cargo.toml`, `kernel/Cargo.lock`, `kernel/src/drivers/{gpu_i14,gpu_i10,gpu_tur}.rs`, `kernel/src/shell/{ciclu,mod}.rs`,
