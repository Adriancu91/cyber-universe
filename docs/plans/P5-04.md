# P5-04 — TCP (client)

**Scop:** conexiuni TCP sigure: deschidere, trimitere, primire, închidere, retransmisie.

**Pași**
1. Mașina de stări TCP pentru client (SYN → ESTABLISHED → FIN), numere de secvență, ACK.
2. Retransmisie cu temporizator (RTO simplu), fereastră de primire, segmente în ordine greșită păstrate.
3. Fără funcții avansate la început (SACK, scalarea ferestrei doar dacă serverul o cere).

**Fișiere:** `kernel/src/net/tcp.rs`.

**Test:** scenariu `tcp`: `tools/test.sh` pornește `python3 -m http.server` pe gazdă; nucleul se conectează la
10.0.2.2:<port>, trimite `GET /`, primește pagina și verifică un text cunoscut; un al doilea test pierde pachete
(opțiune QEMU sau server care întârzie) ca să dovedească retransmisia.

**Riscuri:** cazuri-limită ale mașinii de stări; se testează cu captură de pachete (`-object filter-dump`) la nevoie.

**Surse:** RFC 9293 (TCP), RFC 6298 (temporizatorul de retransmisie).

**Notă la final (2026-10-20):** pierderile se fac cu cârlige de test în nucleu (`DROP_NEXT_SEND`, `DROP_RECV_AFTER`,
doar în build-ul de test), nu cu QEMU — mai sigur și repetabil. Între nucleu și serverul Python stă rețeaua „user” a QEMU
(care are TCP-ul ei); pe calculatorul real se verifică cu `http <site> 80` după P3-09. Fereastra de primire e 16 KiB.
