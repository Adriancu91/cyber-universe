# P6-255 — `token32_v2c`: programul cu ceas după `token32_v2` (`--token32-v2c`)

**Scop:** PREDARE Cyber-GPU sesiunea 274 (P2zzq, `e117394`, nota `integration/cyber-universe/C-157_P2zzq_token32-v2c-ceas.md`).
Un program de **măsurat**: `token32_v2` (aceeași aritmetică) plus citirea ceasului SM-ului la începutul / sfârșitul fiecărei operații,
scrisă într-o zonă separată din memoria plăcii. Arată unde stau cele ~0,67 ms în plus ale lui `token32_v2` față de lista obișnuită.

**Pași:**
1. Dependența `cyber-gpu` `310cbfb` → `e117394` (doar adăugări: `nvidia_ga104::token_clock`, `gpu_sim::cmdproc::token32c_on_cpu`).
2. Opțiunea `--token32-v2c` în ciclu, doar imediat după `--token32-v2`; `gpu_tur::TOKEN32_V2C_IN_CYCLE`; în build-ul de test
   `gpu token32-sim v2c`; modelul `token32c_on_cpu` înregistrat în SIMULARE.
3. `gpu_i14::token32_runs` cu felul `token32_v2c`: doar G = 768 (SM-uri × 16), doar după un `token32_v2` care a trecut la toate G;
   programul `TOKEN32_V2C` (SHA-256 verificat), zona ceasului `4 · clock_words(n, 768)` octeți în VRAM, bufferul constant
   `token_cbuf_clock`, QMD `token32_v2c_qmd_wide` (99 registre, NU `token32_qmd_wide`), lista scrisă doar unde se schimbă (ca v2).
4. Zona ceasului se citește o dată la sfârșitul fiecărui text (programul rescrie fiecare cuvânt la fiecare simbol, deci ea conține
   **ultimul simbol**): `read_clock` → `by_part(parts_of(lista ultimului simbol))` → `rows(timpul plăcii al ultimului simbol)`.
   În jurnal rândurile `kc …` (7 de sumar + 3 pe fel) ale ultimului text. Zona refuzată = un rând de eroare, mergem mai departe.
   Citirea după text (nu după fiecare simbol) ține timpul „cu driverul” al simbolurilor neatins.

**Fișiere:** `kernel/Cargo.toml`, `kernel/Cargo.lock`, `kernel/src/drivers/{gpu_i14,gpu_i10,gpu_tur}.rs`,
`kernel/src/shell/{ciclu,mod}.rs`, `tests/scenarios.txt`, `tests/durate-ci.txt`.

**Test:** `kronos-gpu-token32-v2c` (SIMULARE: G = 768 TRECE, rândurile `kc` cu numerele inventate de model), `kronos-gpu-token32-v2`,
`kronos-gpu-token32` (neschimbate), `ciclu::self_test` (forma rândului), `boot`.

**Rândul pentru teste.txt:** `test-placa --tablou-viteza --token32 --token32-v2 --token32-v2c`.

**Nou pentru placă:** doar programul `token32_v2c` (citiri ale ceasului SM, scrieri în memoria noastră); nicio scriere nouă în registre.
Așteptat (DEDUS, Cyber-GPU C1–C8): aceiași biți; placa ≤ +3 % față de v2; ceasul SM dedus 1 400–2 000 MHz; bariera după cel mai
lent 0,14–0,40 ms; înmulțirile ≥ 0,40 ms peste listă; ln + argmax 0,05–0,20 ms; citiri contor ×10 ≥ 200; atenția ≤ ×1,3.

**Riscuri:** QMD greșit (92 în loc de 99 registre) ar strica registrele — folosim doar `token32_v2c_qmd_wide`. Limita de 100 ms pe
lansare rămâne.
