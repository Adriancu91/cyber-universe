# P6-88 — C-118 pasul W0: `wifi identifica` (Wi-Fi Intel AX201 pe laptopul ASUS), DOAR CITIRE

**Scop:** primul pas din C-118 („da” de la Adrian, 13 nov 01:05): OS-ul găsește placa Wi-Fi Intel (AX201, `8086:43F0`,
CNVi la `00:14.3`) și scrie tot ce se poate afla **fără nicio scriere**: configurația PCI, BAR0, starea de alimentare,
legătura PCIe (dacă are), și — numai dacă firmware-ul a lăsat placa în D0 cu Memory Space pornit — câteva registre CSR
documentate de iwlwifi (versiunea hardware, ID-ul radioului, starea MAC-ului, comutatorul radio). Rândul intră în
`test tot` și în inventarul `analiza` (C-117). Pașii W1–W4 (firmware, scanare, WPA2) vin după poza W0 de pe laptop.

**Pași**
1. `kernel/src/drivers/wifi.rs` (nou): caută funcțiile PCI clasa 02:80 de la Intel (8086); pentru fiecare: ID-uri,
   subsistem, revizie, integrat în PCH (magistrala 0 = CNVi) sau pe M.2, Command, starea D0–D3, BAR-urile, legătura PCIe,
   lista de capabilități. Registrele CSR: `HW_IF_CONFIG` (0x000), `RESET` (0x020), `GP_CNTRL` (0x024), `HW_REV` (0x028),
   `HW_RF_ID` (0x09C), citite prin fereastra doar-citire fără cache a nivelului 0 GPU (fără drept de scriere în tabela de pagini).
   Refuză citirea registrelor dacă placa nu e în D0 sau dacă Memory Space e oprit (nu-l pornim: ar fi o scriere).
2. Decodarea (funcție pură, testată): câmpul de tip din `HW_REV` (biții 15:4) și din `HW_RF_ID` (biții 23:12), biții
   MAC_CLOCK_READY / INIT_DONE / comutatorul radio din `GP_CNTRL`; numele (Qu, QuZ, HR…) = INFERRED (dedus din iwlwifi).
3. Shell: `wifi` / `wifi identifica` (plus `--sim` doar în build-ul de test: ia dispozitivul QEMU `edu` drept placă, ca
   să probeze drumul real de citire MMIO). Lista albă automată/hub: `wifi` și `wifi identifica` (doar citesc).
4. `test tot`: verificarea „wifi” (LIPSA dacă nu e placă; PASS cu ID-urile + rezultatul citirii registrelor).
5. `analiza`: componenta `wifi_adapter` (valorile = MEASURED, numele = INFERRED, registre necitite = NOT_TESTED cu motivul).
6. Fișierul `docs/WIFI.md`: ce face fiecare pas W0–W4, sursele permise, ce NU facem (firmware-ul Intel nu se desface).

**Fișiere:** `kernel/src/drivers/wifi.rs`, `kernel/src/drivers/mod.rs`, `kernel/src/drivers/gpu.rs` (fereastra `pub(crate)`),

**Test:** scenariul nou `wifi` (QEMU fără placă Wi-Fi: „nicio placa Wi-Fi Intel”, zero scrieri; `wifi identifica --sim`
cu `-device edu`: registrele citite prin fereastră, valoarea de identificare `edu` = `010000ed` la 0x000; testul de
decodare cu valori fixe). `analiza-gpu` (`--sim`) cu `-device edu` → componenta `wifi_adapter` în JSON. `testtot` → rândul
„wifi”. Restul suitei neschimbat.

**Riscuri:** pe laptop firmware-ul poate lăsa Memory Space oprit → registrele rămân necitite (NOT_TESTED) până la un pas
cu „DA” (ca la GPU). CNVi poate da `HW_RF_ID` = 0 până la pornirea MAC-ului (iwlwifi îl citește după „trezire”) — se
notează, nu se trezește. Numele de tip sunt deduse; valorile brute rămân în raport.
