# P6-07 — CI publică un GitHub Release cu fișierele stick-ului

**Scop:** ultima versiune bună a OS-ului se descarcă fără autentificare (artefactele CI cer cont GitHub).

**Pași**
1. În CI, după testele verzi pe `main`: un Release (sau o etichetă care se mută, ex. `ultima`) cu fișierele variantei B din
   `docs/USB.md` (`BOOTX64.EFI`, `kernel`, `initrd.tar`, `limine.conf`, `limine-uefi-cd.bin`), imaginea întreagă și
   `SHA256SUMS` (+ un fișier `VERSIUNE` cu commit-ul).
2. Permisiunea `contents: write` doar pentru pasul respectiv; păstrează ultimele câteva versiuni.

**Fișiere:** `.github/workflows/ci.yml`, `docs/USB.md` (descărcarea devine: Releases → ultima).

**Test:** rularea CI creează Release-ul; un script de verificare descarcă fișierele și verifică sumele.

**Riscuri:** permisiuni CI; mărimea fișierelor (câțiva MB — fără problemă).

**Surse:** documentația publică GitHub Actions și REST API (Releases).

**Rezultat (2026-10-21):** jobul `release` din CI (doar pe `main`, după `build-and-test` verde; singurul cu `contents: write`)
publică `os-<număr>` marcat *Latest* cu fișierele variantei B (fără dosare), imaginea întreagă, `VERSIUNE`, `SHA256SUMS`
(`tools/release-files.sh`) și șterge versiunile mai vechi decât ultimele 5. Verificare: `GH_TOKEN=… tools/check-release.sh`
(depozitul e privat → descărcarea cere un token; vezi nota din P6-08).
