# P5-16 — HTTPS în Cyber Universe (`fetch https://…`)

**Scop:** un program din OS descarcă o pagină prin HTTPS și refuză un certificat greșit.

**Pași**
1. Programul `fetch` primește adrese `https://nume[:port]/cale`; folosește biblioteca `tls/` (P5-06) peste `net::TcpStream`.
2. Rădăcinile de încredere: o listă mică de certificate în `/etc/certs/` (în initrd); ora din ceasul RTC pentru valabilitate.
3. Numere aleatoare pentru cheia X25519 și `random`: RDRAND când există, altfel amestec din TSC (SHA-256), printr-un apel de sistem.
4. Bufferele TLS sunt `static mut` (programele n-au heap; stiva e 64 KiB).

**Fișiere:** `user/src/bin/fetch.rs`, `user/Cargo.toml`, apel de sistem pentru aleator în `kernel/src/syscall/`, initrd de test.

**Test:** scenariul `https`: server Python `ssl` pe gazdă (10.0.2.2) cu certificat de test, rădăcina în initrd-ul de test;
`fetch https://…` descarcă pagina; un al doilea server cu certificat pentru alt nume e refuzat.

**Riscuri:** ora din RTC în emulator (QEMU dă ora gazdei); viteza RSA/ECDSA în emulare (măsurată la P5-13/P5-14: sub o secundă).

**Surse:** RFC 8446, RFC 2818 (HTTP peste TLS), documentația Intel pentru RDRAND.
