# P6-201 — proba ocupării: treapta memoriei comune din QMD (`--ocupare`)

**Scop:** PREDARE Cyber-GPU sesiunea 224 (`54f5ab8`, nota `C-165_proba-ocuparii.md`, studiul centrului 25 nov 07:00):
aceeași memorie comună pe bloc, dar **treapta unității** (cât din L1 devine memorie comună) aleasă de noi
(`ComputeQmd::to_bytes_with_sm_config`, `MIN = TARGET = treapta`, `MAX` ca azi). Întrebarea: încap mai multe blocuri
pe unitate și merge înmulțirea mai repede (H1), sau placa urcă deja singură treapta (H2)?

**Pași:**
1. cyber-gpu `ebbb3af` → `54f5ab8` (strămoș verificat, doar adăugări).
2. `ciclu`: sufixul `--ocupare`, doar imediat după `--cursa-mm` (ca `--proba-64k8`, nu amândouă)
   (`ciclu::TRAIN_513_OCCUPANCY`, `gpu_tur::TRAIN_513_OCCUPANCY_IN_CYCLE`); textul de început al testului spune ce face.
3. `gpu_i14::train_513_resident`: cu proba, în locul cursei mari: doar forma qkv, cele 10 rulări din
   `occupancy::PROBE` (`mm_train_tile` 8 → 16 → 32 → 64 KiB, `mm_tv_64x64k8` 8 → 16 → 32, `mm_tv_128x128` 8 → 16 → 32),
   fiecare cu QMD-ul `to_bytes_with_sm_config(shared, treapta)`; același drum de umplere, lansare (1 încălzire + 7
   cronometrate) și citire ca în cursă; martorul biților = prima rulare (lansarea de azi). După fiecare rulare, o citire
   a tabloului de bord (puterea medie).
4. Rânduri: `ocupare <program> <N> KiB: <us> us, <TFLOP/s>, <W> W, ACEIASI BITI` / `DIFERA` / `NETERMINATA`, apoi
   `proba ocuparii: <k> / 10 aceiasi biti`, raportul 64 / 8 KiB la martor și verdictul H1 / H2 (pragurile din notă:
   ≤ 0,85 = H1, în ±3 % = H2) + rândurile de jurnal `kt proba ocuparii ...`.
5. SIMULARE: `gpu antrenare-mini-sim vram-513-ocupare` + scenariul `kronos-gpu-antrenare-513-ocupare`
   (modelul nu are ocupare: verifică doar că QMD-ul cu altă treaptă e citit și dă aceiași biți).
