# P6-68 — Reparația lui I8 (secvențiatorul GSP) în OS + Release nou (comanda C-91 pct. 2)

## Scop
Testul de luni 9 nov (`os-275`, `rezultate/2026-11-09-workstation-os275/` în hub) s-a oprit la `i8-gsp-init`:
„argument invalid: secventiator: marime sau index in afara bufferului”. Eroarea e în cyber-gpu (`decode_sequencer`),
nu pe placă. cyber-gpu repară (C-91 pct. 1); OS-ul ia commit-ul nou și scoate imediat un Release cu CI verde,
ideal până la ~12:30 ora României (Adrian revine la workstation până la ~13:00).

## Pași
1. Diagnostic (doar citire în cyber-gpu, nimic schimbat acolo) → hub `idei/2026-11-09_C-91-cauza-secventiator.md`.
2. Când apare commit-ul cyber-gpu cu reparația: `kernel/Cargo.toml` pe noul `rev` (toate cele 5 crate-uri),
   `tools/after-gpu.sh` / sumele SHA dacă s-au schimbat fișierele verificate.
3. `tools/build.sh`, `tools/test.sh gpu gpu-sim gpu-i6 gpu-scrie gpu-ro gpu-tur kronos-gpu boot shell`.
4. Commit + push pe `main` → CI verde → Release nou; în hub `stare/cyber-universe.md` lista scurtă pentru Adrian
   (aceeași ca P6-63, doar Release-ul nou).

## Fișiere
`kernel/Cargo.toml`, `Cargo.lock`, eventual `tools/after-gpu.sh`, `docs/TASKS.md`, `docs/STATE.md`.

## Test
Scenariile GPU din QEMU (SIMULARE) trec ca înainte; CI verde (cele trei părți). Pe placă: doar Adrian, cu `gpu lant` + DA.

## Riscuri
- cyber-gpu nu publică reparația până la termen → OS-ul nu poate repara singur (regula: nu modificăm codul altui proiect);
  se notează în hub și Adrian află ora.
- După secvențiator pot apărea alte diferențe placă/simulare la I8; lanțul se oprește cinstit la primul pas greșit.
