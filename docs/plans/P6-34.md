# P6-34 — CI: `CYBER_GPU_TOKEN` ascuns de credențialele lăsate de `actions/checkout` (C-37)

## Scop
Adrian a pus secretul `CYBER_GPU_TOKEN` (fine-grained, doar `cyber-gpu`, Contents: Read-only), dar pasul `tools/ci-cyber-gpu-acces.sh`
tot pică („GitHub refuza cyber-gpu”, run 40774740427, încercarea 3). `actions/checkout@v4` salvează în configul local al depozitului antetul
`http.https://github.com/.extraheader` cu `github.token`; `git ls-remote` rulat în dosarul de lucru trimite acel antet în locul cheii din URL,
iar `github.token` nu vede `cyber-gpu`.

## Pași
1. `persist-credentials: false` la checkout-ul jobului de build din `ci.yml` și la cel din `stress.yml` (jobul `release` are checkout-ul lui, neatins).
2. `tools/ci-cyber-gpu-acces.sh`: verificarea rulează cu `git -c http.https://github.com/.extraheader= -c http.extraheader=` din `$HOME`
   (în afara depozitului), ca un antet rămas să nu mai poată ascunde cheia; cheia nu se afișează niciodată.
3. Push → CI; confirmă că pasul trece. Dacă GitHub tot refuză, mesajul exact merge în `stare/cyber-universe.md` (atunci e cheia).

## Fișiere
`.github/workflows/ci.yml`, `.github/workflows/stress.yml`, `tools/ci-cyber-gpu-acces.sh`.

## Test
Local: un depozit de probă cu antetul `extraheader` pus ca la checkout → scriptul ignoră antetul (verificat cu `GIT_TRACE_CURL` că nu se
trimite `AUTHORIZATION: basic` din antet); fără token → mesajul clar; YAML valid. În CI: pasul „Acces la cyber-gpu” verde.

## Riscuri
Fără credențiale persistente, pașii de build nu mai pot scrie în repo — nu au nevoie (doar jobul `release` scrie, cu checkout propriu).

## Surse
