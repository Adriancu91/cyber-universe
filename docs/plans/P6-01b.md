# P6-01b — Recepția pe placa Realtek (după testul 2, comanda C-4)

**Scop:** pe laptopul Lenovo, placa Realtek primește pachete (DHCP, ping).

**Ce s-a văzut (testul 2):** MAC citit corect, 4 pachete trimise, 0 primite; ledul mufei aprins.

**Pași**
1. PHY: registrul MII 0 (BMCR) scris prin `PHYAR` — fără „power down”, auto-negociere repornită; așteptarea legăturii (max. 4 s).
2. La fiecare citire: biții de stare din `ISR` se șterg (unele revizii opresc primirea cât timp „FIFO plin” / „fără descriptor”
   rămâne setat); istoria lor e păstrată (`isr_seen`).
3. Diagnostic: la pornire, în jurnal, registrele citite înapoi (CR, RCR, TCR, IMR, ISR, RMS, RDSAR/TNPDS comparate cu adresele
   inelelor, PHYstatus); `net` arată legătura (viteză, duplex), pachetele pierdute de placă (MPC), ISR văzut, starea următorului
   descriptor RX; la DHCP fără răspuns aceeași linie intră în jurnal (primul minut). `log rtl` le arată pe ecran.
4. Dacă testul 3 tot arată 0 primite: din registrele citite înapoi se vede ce nu a „prins” (RCR, RDSAR, CR) → pasul următor.

**Fișiere:** `rtl8168/src/{lib,model,tests}.rs`, `kernel/src/drivers/rtl8168.rs`, `kernel/src/net/mod.rs`, `kernel/src/shell/mod.rs`.

**Test:** `cd rtl8168 && cargo test --release`; pe laptop: testul 3 (`log rtl`, `net`, `ping 1.1.1.1`).

**Riscuri:** reviziile noi ale cipului (RTL8111H pe laptopuri Ryzen) pot cere setări nedescrise în documentația publică.

**Surse:** fișele tehnice publice RTL8169/RTL8111 (registre), IEEE 802.3 clauza 22 (registrele MII ale PHY-ului).
