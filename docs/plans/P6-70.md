# P6-70 — Reparația C-99 (I8 „timeout după 2 s” la CORE_RESUME) + așteptarea lungă cu Esc (ideea lui Adrian) + Release nou

## Scop
Testul din 10 nov (`os-277`, hub `rezultate/2026-11-10-workstation-os277/`): 0xbadf5620 a dispărut, secvențiatorul rulează
419 din 420 de comenzi, dar la `CORE_RESUME` scrierea de pornire a SEC2 în `CPUCTL` (0x840100) e ignorată (registrul arată
`0x50` = HALTED | ALIAS_EN după Booter) → „timeout după 2 s”. cyber-gpu a reparat (`3fe11f9`: pornire prin `CPUCTL_ALIAS`,
0x840130) și a pus ideea lui Adrian (`3aed5eb`): așteptările I8 de după sonerie au 60 s, jurnalul notează după cât a venit
răspunsul, iar `Clock::abort_requested` oprește așteptarea. OS-ul leagă commit-ul și tasta Esc, apoi scoate un Release.

## Pași
1. `kernel/Cargo.toml` pe `rev = "3aed5eb"` (toate crate-urile cyber-gpu), `CYBER_GPU_REV`, `tests/scenarios.txt`.
2. `keyboard::take_escape()`: ia un Esc din coada tastaturii (cu tastele de dinainte), fără Esc nu ia nimic.
3. `TscClock::abort_requested`: Esc → `true` (eroarea „oprit manual după N us”); cât timp așteptarea continuă, un rând pe
   ecran la fiecare 2 s: „gpu0: astept raspunsul placii (GSP)... N s (Esc opreste)”.
4. `gpu_i8.rs`: așteptarea antetului cozii de stare după sonerie 2 s → 60 s (`sequencer::LONG_WAIT_US`), cu Esc, și rândul
   „asteptat I8 antetul cozii de stare (de la sonerie): raspuns dupa N us”.
5. Test nou la pornire (`test: gpu Esc OK`) în scenariul `gpu`; `tools/build.sh`, `tools/test.sh gpu gpu-sim gpu-i6 gpu-scrie gpu-ro gpu-tur kronos-gpu boot shell`.
6. Commit + push pe `main` → CI verde → Release nou; în hub lista pentru Adrian.

## Riscuri
- Esc funcționează în consola de text (`cyber>`), nu într-o fereastră de terminal din desktop (tastele merg acolo la fereastră).
- O așteptare care nu primește răspuns durează acum până la 60 s (nu 2 s); Esc o scurtează.
- Tastele apăsate înainte de Esc, în timpul lanțului, se pierd odată cu Esc (intenționat).
