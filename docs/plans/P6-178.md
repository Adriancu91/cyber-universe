# P6-178 — `test-placa --antrenare-mini --vram --lot-ram`: lotul și rezultatele pasului prin RAM

**Scop:** PREDARE Cyber-GPU sesiunea 202 (nota `C-157_P2s_lot-prin-ram.md`, commit `d173a59`, C-157 p.2 după os-390).
În os-390 pasul întreg a fost 4 150 µs, din care ~525 µs în afara plăcii, mai ales lotul (321 de cuvinte) scris prin
fereastra VRAM (~290 µs) și pierderile + norma citite prin fereastră (70 µs). Acum procesorul scrie lotul în RAM fixată,
iar programul de copiere (deja pe placă din os-390) îl duce în arenă **în lista pasului** (5 copieri la început, 2 la
sfârșit pentru pierderi + normă). **Niciun program nou pentru placă**, doar 7 copieri mici în listă.

**Pași:**
1. cyber-gpu `477ed55` → `dc54f01` (strămoș verificat: `d173a59` + reparația clippy `as_chunks`; doar adăugări,
   modulul `nvidia_ga104::batch_ram`).
2. `gpu_i14::train_mini_resident(…, via_ram)`: zona de tranzit = începutul lui `stage` (RAM-ul fixat al arenei);
   pe fiecare pas `batch_ram::via_ram` + scrierea în `stage` (nu `ram_write`, care ar șterge ~26 MiB),
   `pack_via_ram` în locul lui `ts::pack`, înregistrările pentru `n_launch + 7`, rezultatele din `stage` cu
   `batch_ram::results`. Drumul vechi (fereastra) rămâne neschimbat.
3. Cu `--lot-ram`: rularea de două ori din aceeași stare (fereastra, apoi RAM) + `ram_verdict`: bit cu bit
   (pierderea și norma la fiecare pas, toate greutățile la sfârșit), pasul întreg și bucățile fereastră → RAM.
   Rânduri `kt antrenare-mini lot prin RAM (1/0)` și `… = prin fereastra bit cu bit (pasi)`.
4. Ciclul: `--lot-ram` doar imediat după `--vram` (nu cu `--pas-lipit` / `--antrenare-513`); build de test:
   `gpu antrenare-mini-sim vram-ram`.
