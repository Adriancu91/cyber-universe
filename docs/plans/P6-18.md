# P6-18 — CI mai econom + Release-ul cu munca din C-14 (comanda C-15)

## Scop
- CI-ul GitHub pornește din nou (repo-ul e public din 2026-10-23 19:05: Actions gratuit) și face Release-ul cu K6-02b, K6-03, K6-04.
- CI-ul consumă mai puțin: nu rulează la commit-uri doar cu documente; o rulare nouă pe aceeași ramură o anulează pe cea veche;
  testul de stres o dată pe săptămână.
- B-004 închis în `docs/BLOCKERS.md` cu cauza exactă; `docs/USB.md` spune că `actualizeaza` merge fără token.

## Pași
1. Verifică vizibilitatea repo-ului (public).
2. `ci.yml`: `paths-ignore` pentru `docs/**`, `**/*.md`, `tests/screens/**` (la `push` și `pull_request`); `concurrency`
   (`ci-${{ github.ref }}`, `cancel-in-progress: true`); cache-ul include și `*/target` (crypto, tls, json, rtl8168, e1000e) și
   cheia ține cont de toate `Cargo.lock`.
3. `stress.yml`: cron săptămânal (luni).
4. Release: rămâne doar la push pe `main` cu teste verzi → cu `paths-ignore`, Release-ul iese doar când s-a schimbat codul.
5. Push → verifică rularea; Release-ul `os-<n>`.
6. BLOCKERS (B-004 → Rezolvate), USB.md (token opțional, necesar doar pentru `gh-trimite`).

## Fișiere
`.github/workflows/ci.yml`, `.github/workflows/stress.yml`, `docs/BLOCKERS.md`, `docs/USB.md`, `docs/TASKS.md`, `docs/STATE.md`.

## Test
- CI verde pe commit-ul cu schimbarea workflow-ului (fișierul `.yml` nu e ignorat) → Release nou.
- Commit-ul următor doar cu `docs/` nu pornește nicio rulare.

## Riscuri
- `concurrency` poate anula o rulare de pe `main` înainte de Release dacă vin două push-uri cu cod la rând: Release-ul iese din a doua.
- Cache-ul crește; GitHub păstrează 10 GB per repo, vechile intrări se șterg singure.

## Surse
Documentația publică GitHub Actions: `on.push.paths-ignore`, `concurrency`, `actions/cache`, `on.schedule`.
