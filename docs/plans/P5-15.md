# P5-15 — Criptografie 6: certificate X.509 și lanțul de încredere

**Scop:** nucleul TLS poate citi certificatele X.509 ale unui server și poate verifica lanțul până la o rădăcină cunoscută.

**Pași**
1. Cititor DER minimal (TLV, lungimi scurte/lungi, refuz pentru codări ne-DER).
2. X.509 (RFC 5280): versiune, emitent, subiect, valabilitate (UTCTime/GeneralizedTime), cheia publică (RSA sau P-256),
   extensiile de bază (numele DNS alternative, „basic constraints”, „key usage”), algoritmul și semnătura.
3. Lanțul: fiecare certificat semnat de următorul (RSA de la P5-13, ECDSA de la P5-14), emitent = subiect,
   rădăcina din lista de încredere, data în interval, numele serverului potrivit (inclusiv `*.`).

**Fișiere:** `crypto/src/der.rs`, `crypto/src/x509.rs`, vectori în `crypto/src/vectors.rs`, scenariul `crypto`.

**Test:** certificate generate cu `openssl` (rădăcină RSA + intermediar + server P-256 și invers), puse ca vectori;
lanțul bun trece; semnătură stricată, nume greșit, certificat expirat, rădăcină necunoscută refuzate.

**Riscuri:** DER are multe forme; citim doar ce ne trebuie și refuzăm restul (mai bine refuzat decât acceptat greșit).

**Surse:** RFC 5280, ITU-T X.690 (DER), RFC 6125 (potrivirea numelui).
