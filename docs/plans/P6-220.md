# P6-220 — agentul de bord: propuneri de cod pe o ramură `agent/…` (C-166 pasul 5)

**Scop:** comanda C-166 a lui Adrian, pasul 5: agentul poate scrie o modificare ca **propunere** pe o ramură
`agent/<data>-<subiect>` din `cyber-universe` — niciodată `main` — cu explicația și dovada; sesiunea OS o verifică, o
testează în QEMU și o trece prin regulile obișnuite. Totul hotărât de OS (codul din `user/src/agent_tools.rs`), nu de model.

**Pași:**
1. `github.rs`: `get_file` (un fișier sau un dosar dintr-un depozit, pe o ramură), `create_branch` (din vârful lui
   `main`; dacă ramura există deja → refuz, nu scrie peste altă propunere), `put_contents_on` (ca `put_contents`, pe o ramură).
   Depozitul codului: `cod = …` în `/etc/github.conf` (implicit `Adriancu91/cyber-universe`).
2. Unealta `citeste_cod` (doar citire): un fișier al codului OS-ului de pe `main` (cel mult 32 KiB de la `de_la`) sau
   lista unui dosar — ca agentul să vadă ce vrea să schimbe.
3. Unealta `propune` (`subiect`, `explicatie`, `dovada`, `fisiere: [{cale, continut}]`):
   - ramura = `agent/AAAALLZZ-<subiect>` (subiect: litere mici, cifre, `-`, cel mult 40); doar prefixul `agent/`;
   - cel mult 8 fișiere, fiecare cel mult 128 KiB, căi valide (fără `..`, fără `/` la început); **refuzate** căile din
     `.github/` (lucrările CI), `LICENSE`, `CLAUDE.md` și `docs/DECISIONS.md` (regulile proiectului rămân ale lui Adrian);
   - pe ramură se pune întâi `docs/agent/propuneri/<ramura>.md` (subiectul, explicația, dovada, lista fișierelor, ora),
     apoi fișierele, fiecare cu mesajul „agent (propunere): …”;
   - CI-ul nu rulează pe `agent/**` (doar `main` și `wip/**`), deci o propunere nu pornește nimic singură;
   - fiecare propunere, făcută sau refuzată, se scrie în `<rădăcina agentului>/agent/propuneri.txt`.
4. Tokenul GitHub se citește o dată la începutul unei întrebări (înainte de cheie), apoi drepturile la secrete se dau
   înapoi; fără token uneltele `citeste_cod` / `propune` răspund „lipseste tokenul”.
5. Promptul de sistem: propunerile doar când ți se cere sau când ai găsit o greșeală cu dovadă; niciodată `main`.

**Fișiere:** `user/src/github.rs`, `user/src/agent_tools.rs`, `user/src/bin/agent.rs`, `tools/claude-test-server.py`,
`kernel/src/main.rs` (`test_agent`), `tests/scenarios.txt`.

**Test:** scenariul `agent`, o întrebare nouă „Fa testul propunerii” după ce imitația GitHub e pusă: `citeste_cod`
(fișier + dosar), `propune` cu `.github/workflows/x.yml` → REFUZAT, `propune` cu subiect greșit → REFUZAT, `propune`
bună → ramura `agent/<zi>-proba` creată + 2 fișiere, a doua oară același subiect → REFUZAT (ramura există); nucleul
verifică `propuneri.txt` (1 făcută, 3 refuzate).

**Riscuri:** o propunere rea pe o ramură nu strică nimic (nimeni nu o unește fără sesiunea OS + regulile); tokenul
trebuie să aibă drept de scriere pe `cyber-universe` — altfel GitHub răspunde 403/404 și agentul spune asta.
