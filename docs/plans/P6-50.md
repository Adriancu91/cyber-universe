# P6-50 — F3: actualizare de sine + revenire automată (C-68)

## Scop
OS-ul ia singur ultimul Release de pe GitHub (HTTPS + SHA-256), păstrează o copie a versiunii vechi, pornește versiunea nouă și revine singur dacă cea nouă nu ajunge la shell. Rapoartele se urcă în hub cu un token cu drepturi minime, aflat doar pe stick.

## Pași
1. Plecăm de la `/bin/actualizeaza` (P6-08) și `fetch`/`ghpush` existente.
2. Backup: `boot/kernel` și `boot/initrd.tar` copiate în `boot/vechi/` înainte de înlocuire.
3. Revenire: un fișier `incercare` scris înainte de repornire; dacă la pornire există și nu a fost șters de shell-ul pornit cu bine (după N secunde), Limine pornește intrarea „vechi” (meniu cu două intrări, implicit cea nouă, contorul în fișier).
4. Rapoartele în hub: doar cu tokenul din `github.token` de pe stick (Adrian îl face).

## Fișiere
`user/src/...actualizeaza`, `boot/limine.conf`, `docs/MASINA_VIRTUALA.md`.

## Test
QEMU cu server local de Release (`tools/update-test-server.py`): actualizare reușită; versiune stricată → revenire la cea veche.

## Riscuri
Limine nu are un contor de încercări propriu → logica de revenire o face OS-ul înainte de pornirea normală.

## Surse
Documentația Limine (CONFIG.md), API-ul GitHub Releases.
