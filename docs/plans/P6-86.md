# P6-86 — C-117 pasul 1: comanda `analiza` („analizatorul UHL” din Cyber Universe), fără placa video

**Scop:** Adrian a făcut în Windows unealta UHL Portable (doar citire, schema `uhl-inventory/0.1`, statusuri CONFIRMED / MEASURED /
DOCUMENTED / INFERRED / UNKNOWN / UNSUPPORTED / NOT_TESTED). Windows nu vede spațiul PCI complet, BAR-urile, toate tabelele ACPI etc.
Cyber Universe le vede: comanda `analiza` scrie pe stick un inventar JSON în aceeași formă, plus o variantă fără numere de serie
și un `report.txt` scurt. `trimite` urcă în hub doar varianta fără serii și raportul. **Doar citire: nicio scriere în dispozitive.**
Partea NVIDIA (BOOT_0/BOOT_42, GFW, antetele VBIOS, VRAM, WPR2 prin cyber-gpu, lista sigură C-54) = pasul 2 (P6-87), după P6-85.

**Pași**
1. `kernel/src/hw/uhl.rs`: construiește documentul (`cyber_json`): `schema`, `tool`, `generated_at`, `machine`, `session`,
   `statuses` (cele 7, cu înțelesul), `sources` (SMBIOS, ACPI, configurația PCI, specificația PCIe, CPUID, harta de memorie Limine,
   XHCI, tabelul nostru de nume), `components` (fiecare cu `id`, `kind`, `name`, `props`: `{value, status, source_refs, sensitive?}`).
   - sistem/placă/BIOS/șasiu/procesor/memorii din SMBIOS (tipurile 0, 1, 2, 3, 4, 17); serialele și UUID-ul = `sensitive`.
   - procesorul din CPUID (furnizor, nume, familie/model/pas, frunze, instrucțiuni); nucleele: MADT vs. pornite = CONFIRMED dacă egale.
   - memoria (harta Limine).
   - **toate** funcțiile PCI: spațiul de configurare 256 B + 4 KiB (hex), antetul, BAR-urile pe index (adresă, tip; mărimea =
     NOT_TESTED, cere o scriere — excepție: BAR-urile cu Resizable BAR, unde mărimea curentă se citește din capabilitate), lista de
     capabilități și capabilitățile extinse, starea D0–D3 (+ ce stări suportă), PCIe (tip de port, legătura max/curentă, ASPM suportat și
     pornit), punțile (magistralele secundară/subordonată).
   - toate tabelele ACPI (fiecare instanță, SSDT ×N): semnătură, revizie, mărime, OEM, OEM table id, creator, adresă.
   - dispozitivele USB enumerate. Placa NVIDIA: `NOT_TESTED` cu nota „pasul 2”.
2. Varianta fără serii: aceleași date, valorile `sensitive` înlocuite cu `[ascuns]`, `redacted: true`.
3. `report.txt`: rezumatul în română (calculatorul, procesorul, memoria, câte dispozitive PCI / tabele ACPI / USB, câte valori pe statusuri).
4. Locul: `<stick>/raport/uhl/<calculator>/<AAAALLZZ-HHMM>/` (`inventory.json`, `inventory.redacted.json`, `report.txt`).
5. `acpi`: lista de tabele crește de la 32 la 128 (laptopul ASUS are 31; alte calculatoare pot avea mai multe).
6. `gh-trimite --rapoarte`: în plus, din `raport/uhl/*/*/` trimite DOAR `inventory.redacted.json` și `report.txt`
   (`rezultate/os-automat/<data>/uhl/<calculator>/<sesiune>/`); `inventory.json` nu pleacă niciodată de pe stick.
7. Shell: `analiza` (și `hw uhl`), ajutorul.

**Fișiere:** `kernel/src/hw/uhl.rs` (nou), `kernel/src/hw/smbios.rs` (tabelul brut păstrat), `kernel/src/hw/mod.rs`, `kernel/src/acpi/mod.rs`,
`kernel/src/shell/mod.rs`, `kernel/Cargo.toml` (`cyber_json`), `user/src/bin/gh-trimite.rs`, `tests/scenarios.txt`, `kernel/src/hw/README.md`.

**Test:** scenariul nou `analiza` (QEMU cu disc de scriere, XHCI, `-smbios` cu serie falsă): fișierele scrise, JSON-ul citit înapoi
cu `cyber_json` în nucleu (valid, schema, componente PCI = numărul de funcții, tabele ACPI), seria falsă prezentă în `inventory.json`
și absentă din varianta fără serii, „0 scrieri in dispozitive”. `ghpush`: un dosar `uhl/` în `/etc/raport` → pleacă doar cele 2 fișiere.
Plus `hw-lista boot shell raport` neschimbate.

`props` cu `status` + `source_refs`, `sensitive`); de comparat cu un `inventory.redacted.json` real din Windows (cerut lui Adrian).
Citirea spațiului de configurare complet e doar citire (ca `lspci -xxxx`); o placă în D3cold răspunde cu FF — se notează, nu se trezește.
