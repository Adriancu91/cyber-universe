# P6-33 — CI cu `cyber-gpu` privat (B-005)

## Scop
Decizia din hub (28 oct 23:35): Adrian a plătit GitHub, Actions repornite. Rularea 201 (a doua încercare) a pornit, dar a picat în 25 s:
cargo nu poate descărca `cyber-gpu` (privat; `github.token` vede doar `cyber-universe`) → 0/81 teste, niciun Release.
CI-ul trebuie să poată citi `cyber-gpu` fără ca vreun repo să devină public și fără să copiem codul altui proiect.

## Pași
1. `tools/ci-cyber-gpu-acces.sh`: cu secretul `CYBER_GPU_TOKEN` (token GitHub doar citire pe `cyber-gpu`), git (și cargo prin
   `net.git-fetch-with-cli`) descarcă `https://github.com/Adriancu91/cyber-gpu` cu token-ul; verifică cu `git ls-remote`.
   Fără secret sau cu token refuzat: un singur mesaj `::error::` clar și oprire.
2. Pasul „Acces la cyber-gpu” după „Verificare mediu” în `ci.yml` și `stress.yml`.
3. Adrian creează token-ul și secretul (pașii în `docs/BLOCKERS.md`, B-005); apoi o rulare nouă (workflow_dispatch sau commit cu cod).

## Fișiere
`tools/ci-cyber-gpu-acces.sh`, `.github/workflows/ci.yml`, `.github/workflows/stress.yml`.

## Test
Local: fără token → mesajul clar, ieșire 1; cu token greșit → „GitHub refuza”, ieșire 1; YAML valid. În CI: după secret, suita completă verde + Release.

## Riscuri
Token-ul expiră (se alege o dată de expirare) → CI pică din nou cu mesajul clar, nu cu 81 de erori. GitHub ascunde secretul în jurnale.
