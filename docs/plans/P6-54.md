# P6-54 — F2 pas 2: criptarea consolei remote (C-68)

## Scop
Consola text prin rețea (P6-49) devine criptată și autentificată cu cheia comună de pe stick: nimeni din rețea fără cheie
nu poate citi sau schimba sesiunea, iar cheia nu mai circulă prin rețea. Clientul rămâne doar Python standard (Windows).

## Pași
1. `kernel/src/net/remote_crypto.rs`: salut X25519 (valori noi la fiecare conexiune), cheile recordurilor din HKDF-SHA256
   (sare = SHA-256 din cheie, transcriptul ambelor saluturi), recorduri ChaCha20-Poly1305 cu contor pe direcție.
2. `remote.rs`: salutul `CYBER-REMOTE 2`, primul record al clientului (`AUTH`) = proba cheii; tot restul sesiunii în recorduri.
   Regulile vechi rămân (3 greșite → pauză, 10 → oprire, jurnal, lista albă).
3. `tools/remote-client.py`: aceeași criptografie în Python pur, după RFC 7748, 8439, 5869; `--test` pe vectorii oficiali și pe
   vectorul comun cu nucleul.
4. Documentația (`docs/REMOTE.md`, `kernel/src/net/README.md`), decizia D-016.

## Fișiere
`kernel/src/net/remote_crypto.rs`, `kernel/src/net/remote.rs`, `kernel/src/net/mod.rs`, `tools/remote-client.py`,
`tools/remote-test.py`, `tests/scenarios.txt`, `docs/REMOTE.md`, `docs/DECISIONS.md`.

## Test
Scenariul `remote`: autotestul criptării la pornire (dus-întors, cheie greșită, octet schimbat, record repetat, lungime greșită,
punct de ordin mic, vectorul comun), 3 chei greșite + pauză, un record stricat închide sesiunea, salutul e `CYBER-REMOTE 2`,
sesiunea cu comenzi; `remote-client.py --test`.

## Riscuri
Protocol propriu, nu TLS: păstrat mic și construit doar din piese verificate pe vectori oficiali; fără certificate (cheia comună
ține locul lor). Clientul vechi nu mai merge (mesaj clar). Python pur e lent, dar pentru text ajunge.

## Surse
RFC 8446 §2.2 (ideea PSK + DHE din TLS 1.3), RFC 7748 (X25519), RFC 8439 (ChaCha20-Poly1305), RFC 5869 (HKDF). Cod propriu.
