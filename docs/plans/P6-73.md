# P6-73 — C-104: „agentul de comenzi” din OS — `hub asculta` în buclă + un răspuns pe comandă în hub

## Scop
Adrian vrea un agent în OS care ia singur comenzile centrului de comandă din git („nu trebuie să fie inteligent”).
Există deja `hub ruleaza` (P6-64, o dată, la cerere sau la pornire). Acum: buclă la fiecare N minute, un fișier de răspuns
separat pentru fiecare comandă, aceeași listă albă.

## Pași
1. `hubcmd.rs`: `hub asculta [--la N]` (1–60 min, implicit 2), Esc oprește; `/usb/hub/asculta` (gol sau cu minutele) = buclă
   pornită la pornire pe un fir al sistemului, oprită cu `hub opreste`. O rundă fără nimic nou = un rând, nimic trimis.
2. Fiecare comandă (rulată sau refuzată) → `/usb/hub/raspunsuri/K-<nr>.txt` (secretele ascunse ca în rapoarte) →
   `gh-trimite --raspuns <fisier> K-<nr>` → hub `integrare/cyber-universe/raspunsuri/K-<nr>.txt` (doar acel dosar, ID verificat).
3. Lista albă neschimbată (`gpu lant`, `--scrie`, `DA`, `reboot`, ștergeri, `hub …` refuzate).
4. `docs/USB.md` punctul 15: pașii pentru token (fin, doar `Cyber-hub`, Contents read and write, DOAR pe stick).

## Fișiere
`kernel/src/shell/hubcmd.rs`, `kernel/src/shell/mod.rs`, `kernel/src/main.rs`, `user/src/bin/gh-trimite.rs`, `tests/scenarios.txt`,
`docs/USB.md`, `kernel/src/shell/README.md`.

## Test
`ghpush` (QEMU, serverul de probă GitHub): după `hub ruleaza`, bucla rulează 3 runde la 1 s; în runda 1 apare K-5, în runda 2
nimic nou, în runda 3 K-6 → `facute.txt` = K-1, K-2, K-4, K-5, K-6 (fiecare o dată); răspunsurile K-5, K-6, K-2 (refuzat) se
citesc înapoi din hub; `--raspuns` cu ID greșit refuzat.

## Riscuri
- Bucla pornită la pornire nu citește tastatura (ar fi al doilea cititor) → se oprește cu `hub opreste`, nu cu Esc.
- Fără token / rețea: spune și nu rulează nimic (ca `hub ruleaza`).
- Pe workstation neîncercat (lipsește `github.token` pe stick).
