# P6-200 — proba int8 pe tensor cores `mma16_s8` după P8 (`--p8 --p8-s8`)

**Scop:** PREDARE Cyber-GPU sesiunea 223 (`ebbb3af`, nota `integration/cyber-universe/B1_mma16-s8.md`, pista B1):
Mesa NAK scoate înmulțirea int8 pe tensor cores (`imma.m16n8k32.i8.i8`). Programul de probă `mma16_s8` face
`D[16,16] = A[16,32] · B[32,16] + C[16,16]` (A, B întregi pe 8 biți cu semn; C, D întregi pe 32 de biți). La întregi
nu se rotunjește nimic, deci verdictul e **bit cu bit** față de oracolul pe procesor. Legat acum în OS (SIMULARE);
**pe placă abia după `mm_tc` (os-352 / os-384) și cursa cu 5 variante (os-421)** — ordinea o alege centrul.

**Pași:**
1. Dependența cyber-gpu `2a1dbb4` → `ebbb3af` (strămoș verificat; doar adăugări).
2. `ciclu`: sufixul `--p8-s8`, doar imediat după `--p8` (`ciclu::P8_S8`, `gpu_tur::P8_S8_IN_CYCLE`); textul de început
   al testului spune ce face.
3. `gpu_i14::mma16_probe`: cu sufixul, după cele 6 seturi f16: programul `mma16_s8` (SHA-256 verificat, mapat cu
   `qmd::program_map_bytes`), aceeași pagină de RAM (A la +0, B la +0x200, C la +0x400, D la +0x800), `cbuf_s8` +
   `qmd_s8`. 11 seturi: 8 aleatoare (același generator ca T229, semințele 1–8), 3 margini (−128 × −128 + C = −3,
   −128 × 127 + C = 11, A = [I16 | 0]). D umplut înainte cu `0x7fff_fff7`; oracolul `gpu_compute::mma_s8::mma16_s8_ref`
   (refuză orice set care iese din i32 — niciunul nu iese). O lansare care nu termină oprește proba (fără reîncercare).
4. Rânduri: `mma16_s8 set N (nume): ACEIASI BITI` / `DIFERA la (i, j): placa X, oracol Y (K cuvinte diferite)`, apoi
   `proba mma16_s8: TRECE / NU TRECE / NU A TERMINAT: K / 11 seturi cu aceiasi biti, timp median T ns`; `kt mma16_s8 …`.
5. Placa simulată (`gpu_i10`): `mma16_s8_on_cpu`. SIMULARE: `gpu p8-sim s8` + scenariul `kronos-gpu-p8-s8`.
